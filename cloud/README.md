# FORCE заявки без VPN: российская функция + Google relay

Этот комплект **не развёрнут**. Ветка сохраняет работающий основной сайт без переключения DNS. Клиентский `lead-config.js` пока содержит пустой URL, поэтому на GitHub Pages обе формы из этой ветки не заработают до настройки функции.

## Что нужно настроить

1. В Yandex Cloud создать публично вызываемую Cloud Function на Node.js 20+ из `cloud/lead-function/index.js`, entry point `index.handler`. У функции должен быть HTTPS URL. Проверить вызов с российского подключения, прежде чем менять формы. Cloud Function — небольшой приёмник, не VPS.
2. В переменных окружения функции задать `SITE_ORIGIN=https://club.forcezon.ru`, два Telegram bot token/chat ID (`BOOKING_TELEGRAM_BOT_TOKEN`, `BOOKING_TELEGRAM_CHAT_ID`, `FRANCHISE_TELEGRAM_BOT_TOKEN`, `FRANCHISE_TELEGRAM_CHAT_ID`). Секреты не коммитить. Если прямой Telegram из функции не работает, включить Google relay ниже.
3. В Google Apps Script создать проект из `cloud/google-apps-script/Code.gs`. В *Script properties* задать `RELAY_SECRET` (случайная строка 32+ символа), `BOOKING_BOT_TOKEN`, `BOOKING_CHAT_ID`, `FRANCHISE_BOT_TOKEN`, `FRANCHISE_CHAT_ID`. Развернуть web app: **execute as owner**, доступ **Anyone**. URL `/exec` сохранить как `GOOGLE_RELAY_URL` в функции; ту же строку `RELAY_SECRET` записать как `GOOGLE_RELAY_SECRET` в функции. URL `/dev` не использовать.
4. Сделать помеченные тестовые заявки обоих типов и проверить, что сообщение реально пришло в Telegram. При блокировке прямого вызова функция автоматически пробует Google relay. Ответ формы `ok: true` выдаётся только после подтверждения Telegram.
5. Только после проверки записать HTTPS URL функции в `lead-config.js` и опубликовать статическую часть на основном сайте. В браузере РФ без VPN повторить обе заявки.

Старый токен брони был открыт в публичном JS на main и в истории Git. Перед переключением брони на новую схему отозвать его у BotFather и выдать новый. До переключения отозванный токен сломает текущую бронь.

## Ограничения и защита

- Это не полноценная очередь/резервная копия. При недоступности обоих маршрутов форма получит ошибку, пользователь сможет повторить отправку; не показывать ложное «отправлено». Для гарантированной доставки позже нужна запись заявки в хранилище и повторная отправка.
- `Origin` и CORS не являются защитой от автоматических прямых запросов. Перед боевым запуском настроить ограничение частоты вызовов и антиспам у публичного API/шлюза; иначе злоумышленник сможет спамить бота.
- При таймауте после фактической отправки возможны дубли. Google relay подавляет повторы с одним ID в течение 6 часов, но новая попытка формы получит новый ID.
- В `lead-config.js` допустим только публичный URL. Токены Telegram и relay secret хранятся исключительно в окружении функции и Script Properties.
- Google Apps Script — резервный маршрут **со стороны функции**. Браузер посетителя к Google не обращается.
